# 統合型天気演出の実装状況

現在の仕様は `SPECIFICATION.md`。以前の個別方式の仕様は `archive/SPECIFICATION_INDIVIDUAL_2026-11-17.md` に保存する。

## 統合型の制御

- 新規配置は登録時の初期値が「晴れ」（時刻11.0、曇り具合35、太陽X=160、Y=-200、直径64、風速10、風向0、風表現0）の設定になっている。ホストの編集APIがまだ使えない新規生成時にも、濃い青空・多めの白い積雲・上寄りの太陽を描画できる。
- 「天気プリセット」は初期値一式の呼び出しだけを担当する。選択だけでは描画は変わらない。「設定を反映」の編集APIで40個の数値項目、空の有無、二重虹を保存する。シードは維持する。
- 描画器は天気プリセット番号を受け取らず、現在の設定値だけから全現象を合成する。描画中にホストの項目値を変更しない。
- 統合型の各項目はAviUtl2の標準トラックを使用し、中間点・移動設定による現在値を受け取る。
- 旧版の統合天気の保存名・プリセット選択値を維持する。新しい「虹」「オーロラ」「真夏」を末尾へ追加し17種類とした。旧版の「描画方式」と「スタイル」の登録を外し、描画は現在の天気設定に一本化した。

## UIとSDK

SDKの `FILTER_ITEM_GROUP` を使い、基本設定、雨・雪、風、太陽、月、虹、その他の天候の7グループに分ける。基本設定だけを初期展開し、他は折りたたむ。SDKはグループ名が空の項目を終端として扱う。

最上段の天気プリセットと設定反映ボタンはグループの外へ置く。グループ終端を含む登録項目は59個で、共通登録基盤の上限99個に収まる。名前が重複すると保存項目を区別できないため、太陽X・月X・虹Xのように固有名を使う。

選択変更のコールバックに依存せず、既存AquaFXと同じ `FILTER_ITEM_BUTTON.callback2` と編集APIを使う。ホストが渡した対象オブジェクトとエフェクト名をそのまま使い、同一プラグインの2個目以降へ反映できる。

登録フラグはAquaFXと同じ映像・フィルター・ユーザーデータとする（値25）。メディア入力用のフラグは併用しない。単体のフィルターオブジェクトと、画像・動画へ追加するフィルターとして使う。SDK型配置、ビルドイベント、デバッガー設定は維持している。SDKの標準UIで必要な機能を構成できるため、専用GUIは追加していない。折りたたみの定義は検査済みだが、実機の画面表示は未確認。

## 時刻と曇り具合

時刻は0～240で保存し、描画時に24時間で剰余を取る。空は時刻ごとの上空・地平線・下部の色を滑らかに補間する。高度方向のグラデーション計算は従来の青空と共通化し、昼12時・曇り0の画素は従来の青空と一致させる。

日照と朝夕の暖色は時刻から評価する。曇り具合はパレットの減光・低彩度化、雲の被覆と密度、雲色、太陽光の減衰に使う。雲色も昼の白、朝夕の暖色、夜の暗色を補間する。雨量・雪量の数値は変更しない。

6時・18時付近では `RenderTwilightSky` を使い、下端を地平線とする青紫・赤・橙・黄の色帯を描く。4.75～7.25時、16.75～19.25時で滑らかに増減し、それ以外の時刻は従来の空へ戻る。曇りによって彩度と光を弱める。日中と深夜の描画は変えない。雲を少し金色に照らし、太陽も金色へ寄せる。色の考え方は[気象庁の夕焼けの説明](https://www.jma.go.jp/jma/kishou/know/faq/faq13.html)を参照し、描画は演出向けの近似とする。

色帯は行ごとに計算し、空・天体の既存キャッシュを使用する。雲の合成後に `RenderSolarAtmosphere` で現在の太陽X/Yを中心とする局所光を重ねる。白黄の内側から橙の外側へ3段のガウス分布をスクリーン合成し、背景色と雲の色を残して明るくする。太陽の高さ、透明度、曇り具合、朝夕の時刻によって減衰する。分布の指数計算は行・列ごとに事前計算し、描画範囲を太陽の近傍に制限する。

朝夕プリセットの初期時刻は6/18、夜の曇りは30。朝夕・虹・真夏の配置計算にはSDK標準の `EDIT_SECTION.info` から現在のシーン幅・高さを借用する。朝夕は太陽下端がシーン高さの98%になる座標を保存し、虹と真夏はシーンの縦横に応じて虹と太陽の寸法・位置を保存する。ポインターは保持しない。公式SDKの `EDIT_INFO* info` と幅・高さの配置を確認した。情報がない場合は960×540を基準にする。既存SDK型の順序・サイズは変えていない。

少～中程度の曇りでは、雲の量が増えても空の青さと雲の白さを保つ。空の減光と雲の灰色化は厚い曇天へ近づくほど強める滑らかな曲線とし、雲量からの直線的な減光を避ける。曇り0の青空と、厚い曇りの暗さは維持する。

統合型の晴天では `WeatherFX_Cumulus` が、重なる雲塊と3次元ノイズによる密度・太陽方向の光学的厚さを評価する。白い上面と青灰色の下面を持つ雲の画像を生成し、4段階の遠近で画面に配置する。曇り具合に対して各雲のサイズを滑らかに増やし、風で移流する。部分的な出現量を大きな雲全体の透明度へ使わず、小さな不透明な雲から育てる。縮小段階画像をアルファ乗算で作り、描画格子に応じて連続的に補間し、成長途中の小さな雲のちらつきを防ぐ。

曇り55～75で従来の多段連続ノイズによる厚い被覆へ滑らかに移行し、100ではノイズによる穴を閉じる。厚い被覆のノイズは粗い格子で評価してから補間し、密度に応じて格子間隔を急に切り替えない。曇り0の青空も従来と一致させる。

## 合成と独立配置

1つの描画バッファに、空、星、オーロラ、太陽・月・虹、雲、日差し・月明かり、流れ星、雷、霧、雨・雪、風を順に合成する。必要な場合に最後に屈折を加える。各現象の無効値では計算を省く。

天体と虹の中心は、画面中心に専用X/Yのピクセル値を加えて求める。時刻で移動しない。虹は帯幅と角度を直接指定し、透明度0で主帯を完全表示できる。二重虹は外側の色順を反転し、濃さを下げる。

空を描画するチェックを追加し、背景生成と入力画像への重ね合わせを選べるようにした。オフで全現象を無効にした場合は、入力RGBAをそのまま維持する。メディアオブジェクトの標準描画による全体変形も使用できる。フィルターオブジェクトではSDKの制約に従い画像サイズを維持する。

## 降水と風

雨・雪は従来の固定ハッシュ粒子を再利用する。量を連続的な粒子数の基準へ変換し、画面面積に応じて密度を調整する。雨と雪は同時に描ける。

風速・風向から共通の移流ベクトルを作り、雲の移動、雨・雪の速度ベクトル、霧の移流へ使う。風表現0でもこの影響は残る。風向0と360は同じ方向になる。

風表現を有効にすると不規則に曲がる薄い流線を描く。50を超える強い風表現では画像の弱いゆらぎも加える。流線とゆらぎの強度は連続的に増やす。物体との衝突は行わない。

## 追加した大気現象

変更前の実装では雷・霧・オーロラ・陽炎・蜃気楼・風の流線が未実装だったため、今回追加した。

- 雷：固定シードと時刻から発生イベントを決め、太さを調整できる白い主放電路・分岐・短い再発光と、強度を調整できる全面発光を描く。太さ0で全面発光のみ、全面発光0で雷線のみ。音声なし。
- 霧：白い中性色のもやを、大きく緩やかな濃淡の連続ノイズと縦方向の密度変化で合成する。風によって移動する。プリセットの朝焼け色・積雲は外し、昼の空に白いもやを重ねる。
- オーロラ：複数の時間変化を持つ曲線と細い光の濃淡でカーテンを作り、緑から紫へ色を変える。
- 陽炎：主に下部で変化するノイズ場から座標をずらす。
- 蜃気楼：下部の簡易的な上下反転・伸縮と位置ずれを行う。

屈折では現在の描画結果を複製し、アルファ乗算で4近傍を補間する。他のレイヤーを直接読み取らず、厳密な光学計算や髪・服の物理計算も行わない。

統合型の星は専用サイズを使い、星空の初期値を4とした。流れ星は表示の強さと頻度（回/分）を分ける。頻度ごとの時間区間で発生時刻・寿命・開始位置・軌道をハッシュから決め、現在時刻に関係する区間だけ評価する。逆シークで乱数の状態を進めない。

## 状態・性能・制限

画像バッファ、雲・大気の格子、屈折用の画像複製はエフェクトごとの描画器が所有し、ホストの破棄通知で解放する。ホストのポインターをコールバックの外へ保持しない。

時刻・設定・シードから直接評価し、再生履歴や動画の全長に依存しない。RGBAは非乗算形式で保存し、source-overで合成する。空の塗りつぶし、透明・不透明画素、虹の範囲外、格子補間など従来の短縮経路を再利用する。

統合型の太陽は、月面のような濃淡を避けた高輝度の白い中心と広い周辺光を描き、色を時刻パラメーターで変える。太陽の強さ100%で従来の発光を再現する。上限200%まで中心輝度と周辺光の広がりを増し、100%以下では合成時の不透明度を調整する。真夏の陽炎と蜃気楼には既存の屈折処理を使う。空が全面不透明で秒時刻による変化がない組み合わせは、完成画像をインスタンス内で再利用する。設定全体・シード・解像度が変われば再描画する。入力画像へ重ねる場合や、動く雨・雪・風・星・オーロラ・雷・屈折などでは完成画像を再利用しない。

星・オーロラが無効で空が不透明な場合は、風や降水が動いていても、空と天体の背景画像だけを再利用する。雲の色・透明度の格子セルを共有して画素へ展開し、空白セルと画素ごとの重複計算を減らす。初回の雲生成は視線のXY成分を事前計算して交差しない雲塊を除外する。統合型の雪・星は円の行範囲を絞った粒子描画を使う。全面発光は共通の色・透明度をまとめて計算する。

Debug / Releaseの両構成で本番AUF2を検査EXEから読み込み、`-Profile`で空・太陽・静止雲・移動雲・雨・2種類の雪サイズ・霧・星の初回と準備後5フレームを計測できる。ホスト転送・GPU・実機の再生FPSは含まない。

積雲は無限に続く空間セルの座標と奥行き・シードから固有の形を決める。高さ、左右の非対称性、雲塊の張り出しを変え、固定16画像の繰り返しを廃止した。風で画面外へ流れた後も隣の空間セルから新しい雲が入り続ける。毎フレーム、現在の移流量から必要なセルだけを求めるため、逆シークや初めての途中時刻にも同じ雲を再現する。

雲画像はインスタンス内の最大128件のLRUキャッシュに保持し、初回と新しいセルへの移動・シード変更時に必要な形を生成する。遠景ほど立体格子と画像を小さくし、種類を増やしたことによる負荷を抑える。密度・透過光の作業格子は各雲の生成中だけ所有する。同じセルの移動と色変更では陰影付き画像を再利用する。素材画像の同梱・読込は行わない。初期の晴れは風が有効なので、完成画像を固定して再利用せず雲の位置を毎フレーム更新する。

最大画像サイズは一辺8,192、総画素数16,777,216。粒子数は系統ごとに最大12,000。高密度の降水、強い屈折、多数の同時現象ではCPU負荷が増える。雷・霧・オーロラ・屈折は演出向けの簡易描画であり、見た目と実機負荷の採否は継続確認する。

テスト手順と結果、本番AUF2のハッシュは `../note.md` に記録する。`setup`の内容・配布ZIP・カタログは変更しない。
